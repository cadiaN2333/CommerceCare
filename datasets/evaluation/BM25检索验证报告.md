# 中文 BM25 基线验证报告

本次验证当前 Lucene BM25 独立检索代码，尚未实现或验证 RRF 融合。

## 代码与构建

- Maven clean verify 和修复后 verify 均构建成功；项目目前没有自动化单元测试，以下为实际 HTTP 集成检查。
- Lucene 10.5.2 的 core、analysis-common、queryparser 依赖在当前环境能正常解析并编译。
- 修复 KnowledgeIngestionService 重复调用 vectorStore.add 的问题，将向量写入和 Lucene upsert 一并放在非空判断中，避免重复 Embedding 请求。

## 隔离方式

使用独立端口 18082、临时 Lucene FSDirectory 和独立 pgvector 表，未占用原 8081 服务的 Lucene 索引或业务向量表。验证结束后停止临时进程，并删除本次创建的临时索引目录与向量表。

## 功能验证

| 检查 | 结果 |
|---|---|
| 服务启动与健康检查 | 通过 |
| 空 Lucene 索引搜索 | 返回空数组 |
| 导入四份演示知识 | 4 个 sourceId、5 个片段 |
| 重复导入配对指南 | pgvector 仍为 5 行，Lucene 仍为 5 个唯一片段 |
| 无匹配英文词项 | 返回空数组 |
| 空问题及 topK=0 | 返回 HTTP 400 |
| 查询含 Lucene 特殊字符 | 返回 HTTP 200 |
| 重启后不重新入库 | 仍可查询全部 5 个片段 |

## 同集对照结果

用 multi-source-retrieval-v1 的 8 条问题、TopK=2 对同一批知识分别调用 search 和 keyword-search。按 expectedSourceIds 进行来源级相关性检查；每条返回片段是否相关，仅按其来源是否在标注集合中判断，并非逐片段人工语义标注。

| 路径 | 请求成功 | 平均来源 Recall@2 | 平均来源标记 Precision@2 | 主来源排第一 | 单次串行平均耗时 |
|---|---:|---:|---:|---:|---:|
| pgvector 向量 | 8/8 | 1.0000 | 0.7500 | 8/8 | 242.5 ms |
| Lucene BM25 | 8/8 | 0.9375 | 0.6875 | 8/8 | 15.8 ms |

本次 Precision@2 以配置的 K=2 为分母；两路每题均返回 2 个片段。耗时仅是单次小样本，向量路径含远程 Embedding，不能据此推断生产并发性能。

BM25 在 MR-008 的 Top2 返回售后政策和物流指南，漏掉必要的配对指南，导致该题来源召回为 0.5。MR-002 的第二片段更符合预期来源，但 MR-004 的第二片段变为非预期物流来源。因此 BM25 实现功能已验证，但本组开发数据上未优于纯向量基线。
