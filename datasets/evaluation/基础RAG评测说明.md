# 基础 RAG 开发评测

`basic-rag-cases.json` 包含 12 条静态知识问题：8 条可回答、4 条资料不足。政策来源为 `datasets/knowledge/return-and-warranty.md`，均为项目虚构数据。

## 使用范围

本问题集调用 `POST /api/v1/chat`，固定 `topK = 3`。不要求系统查询或核验订单，不替代原先包含业务工具的 `faq-cases.csv`。

此问题集用于开发检查，已在对话中公开，不能同时作为独立留出评测集。12 条样本只能帮助发现错误，不能据此声称生产环境准确率或拒答可靠性。

## 字段

| 字段 | 用途 |
|---|---|
| caseId | 固定用例编号 |
| group | 普通 FAQ、条件边界、长尾表达或无答案 |
| question | 实际输入 |
| expectedStatus | 预期业务状态 |
| expectedSourceId | 可回答问题的预期来源；无答案问题为 null |
| expectedAnswerPoints | 人工核对答案的要点与不应出现的承诺 |

## 结果判定

自动检查状态是否一致；可回答问题检查来源是否包含预期 sourceId，无答案问题检查 sources 为空。它们只验证接口状态与来源标识，不证明正文正确或每个结论有依据。

答案正文需按 expectedAnswerPoints 人工审核，记录 manualCorrect 为 true 或 false，并补充失败原因。检查是否编造免费维修、收费金额、物流赔付，或声称已核验订单、完成业务操作。

分别记录正确回答、错误回答、误拒答、无依据回答和接口错误。HTTP 502 等服务异常不算正常拒答。

同时记录每次请求耗时，保持模型、资料版本、topK 和问题集一致，后续比较检索优化结果。单次请求耗时不代表并发性能。

## Windows PowerShell 编码

在 Windows PowerShell 5.1 中运行包含中文的 `.ps1` 文件时，使用带 BOM 的 UTF-8 保存。无 BOM 的 UTF-8 可能被按系统编码读取，产生中文乱码以及字符串、括号解析错误。

评测脚本的中文 API 回答需从 HTTP 原始响应字节按 UTF-8 解码后再解析 JSON，避免 Windows PowerShell 5.1 根据响应头猜编码。2026-10-06 首次结果曾出现乱码；切换为读取 HTTP 原始字节并显式按 UTF-8 解码后，第二次结果 CSV 正常可读。


第二次批量调用：12/12 状态匹配，12/12 来源检查匹配。单次串行平均约 1700 ms，最大值/P95 为 3930 ms，仅供当前开发观察。由于知识库来源记录少，来源匹配率不能代表复杂检索召回能力。
