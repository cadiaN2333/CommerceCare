# 扩展电商客服开发评测

本数据集全部为虚构产品、渠道政策与操作说明，不代表真实售后承诺或产品参数。用于增加相似干扰来源，评估模型名称、数值边界、长尾表述和多来源问题。

## 数据组成

- 新增 10 个相近型号，每型号 6 个独立知识来源，共 60 个来源；原有 SoundBee-A1 的 4 个来源继续保留，资料不会覆盖旧规则。
- 主题为无理由退货、质量售后、配对、充电、物流停滞、电子发票。
- `policy-catalog.json` 保存每个型号的模拟参数，`corpus-manifest.json` 保存资料路径、稳定 sourceId 和 SHA256。
- `cases.json` 含 100 条固定问题、预期来源集合及人工答案审核要点。
- 开发集 70 条：56 条可回答检索问题、14 条无答案问题。
- 保留验证集 30 条：24 条可回答检索问题、6 条无答案问题。按型号分组，7 个开发型号与 3 个验证型号不交叉，部分验证问题采用不同表述。

这是合成且公开的开发资料，即使分组保留，也不能称为真实盲测或代表线上业务分布。验证问题的结果被用于调参后，应重新准备独立验证集。

## 一键运行

保持后端在 8081 运行、PostgreSQL 健康，在项目根目录的 PowerShell 执行：

```powershell
.\scripts\run-expanded-evaluation.ps1
```

默认导入全部 60 份资料，再调用开发集的 56 条可回答问题，每题比较 `search`、`keyword-search`、`hybrid-search`，共 168 次检索请求。资料写入会调用远程 Embedding；向量和混合检索也会调用查询 Embedding。运行需要有效模型配置，耗时和费用随服务变化。

后续资料没有变化、数据库与 Lucene 索引没有重建时可以跳过入库：

```powershell
.\scripts\run-expanded-evaluation.ps1 -SkipImport
```

脚本检查入库记录的服务地址与资料清单哈希；该本地记录不能证明索引仍然完整。更换启动工作目录、重建索引或清空数据库后，需要重新导入。

需要测聊天回答和无答案拒答时：

```powershell
.\scripts\run-expanded-evaluation.ps1 -SkipImport -EvaluateChat
```

该模式另调用当前 `/api/v1/chat` 的全部选中问题，默认开发集 70 次。当前聊天端点仍使用原来的向量路径，因此它不是三种检索方式的生成质量对照。自动检查状态与来源，答案仍需人工审阅。

保留验证集由明确的参数选择，不默认运行：

```powershell
.\scripts\run-expanded-evaluation.ps1 -SkipImport -Split validation
```

`-Split all` 会使用两个集合；`-TopK 3` 可对照不同输出数量；`-Limit 10` 用于脚本冒烟检查，不应当作完整评测。

只检查文件格式、来源、型号分组和哈希，不调用任何 API：

```powershell
.\scripts\run-expanded-evaluation.ps1 -ValidateOnly
```

脚本以 UTF-8 BOM 保存，并显式解码 HTTP 原始响应，以兼容 Windows PowerShell 5.1 的中文处理。

## 输出与指标

每次结果位于 `artifacts/evaluation/expanded-v1-分组-时间-进程号/`，目录被 Git 忽略：

| 文件 | 内容 |
|---|---|
| import.csv | 各来源导入的片段数量及失败信息 |
| retrieval.csv | 每题每路的候选来源、Recall、Precision、MRR、耗时、错误 |
| raw-results.jsonl | 完整候选正文、分数和 RRF 两路排名，用于失败案例排查 |
| summary.csv | 三路整体汇总 |
| by-group.csv | 按普通 FAQ、边界、长尾和多来源分组汇总 |
| metadata.json | 数据、脚本、检索服务源码和配置文件哈希、TopK、分组、运行环境及导入状态 |
| report.md | 本次机器生成的摘要，不能代替人工评测报告 |
| chat.csv | 可选的聊天状态、来源、正文和人工审核字段 |

- 来源 Recall@K：命中的预期来源数 / 预期来源总数，再按问题取平均。
- 来源标签 Precision@K：返回片段中来源属于预期集合的片段数 / 配置的 K。同一来源的两个片段按两个候选计数。
- 全部证据召回率：需要的所有来源是否一起出现在 TopK，适合观察组合问题。
- Hit@K：是否至少命中一个预期来源。
- MRR：首个相关来源的排名倒数，未命中为 0。
- 接口错误留在总体指标分母里并记为 0，不算正常拒答，不仅汇总成功请求。
- 单次串行耗时只是开发观察，没有测并发、模型 Token 成本或生产稳定性。

无答案问题没有支持答案的 gold 来源集合，不能简单计算检索 Recall。默认跳过其检索评分；启用聊天模式才检查其拒答状态。来源级标签不等于逐片段语义相关性，更不等于答案正确率或幻觉率。

元数据只记录文件哈希，不读取或保存 API Key。模型服务实际部署版本、环境变量覆盖和随机性仍需额外记录，因此文件哈希不能保证云模型输出完全可重复。

资料首次入库时会增加当前知识库，不删除旧资料。当前入库逻辑未实现资料缩短时旧片段清理；本版本原样重复导入可按稳定 ID 更新，改变切片数的更新需要另行处理。
