# 多来源检索基准

`multi-source-retrieval-cases.json` 是基础 RAG 扩展问题集，用于检查 pgvector 是否能从售后规则、配对指南、物流排查和发票指南中召回预期来源。所有政策、产品步骤和订单场景均为项目虚构数据。

## 先准备知识库

通过现有 `POST /api/v1/knowledge/index` 接口，将下面三份资料分别入库；原有的售后规则资料已入库：

- `soundbee-a1-pairing-guide.md` → `sourceId` 为 `soundbee-a1-pairing-guide-v1`
- `delivery-troubleshooting-guide.md` → `sourceId` 为 `delivery-troubleshooting-v1`
- `soundbee-a1-invoice-guide.md` → `sourceId` 为 `soundbee-a1-invoice-guide-v1`

对应请求样例为同目录下的 `*-index-request.json`。每份知识必须使用自己的稳定 `sourceId`，否则无法区分检索来源。

## 检索测试

对 JSON 中每条用例调用 `POST /api/v1/knowledge/search`，将 `question` 作为问题并使用 `topK = 2`。核对结果的 `sourceId` 是否覆盖 `expectedSourceIds`。MR-006 与 MR-008 是多来源用例，预期的两个来源都应出现在前两项结果中。

本轮先记录来源召回，不评估回答生成。两个必需来源同时命中时可记为该用例 Recall@2 = 1；否则记录漏掉的来源。单次测试只做基线观察，不代表一般化检索效果。

## 限制

- 文档尚未入库前不要运行问题集，否则结果只会来自现有售后规则。
- 当前知识规模很小，适合检查端到端索引和来源映射，不能代表大规模搜索性能。
- 评测问题已公开，后续应额外准备独立留出的验证问题。
- 这些模拟规则不代表真实 SoundBee 产品、物流或商家政策。

首轮结果与指标口径见 [多来源检索评测报告.md](多来源检索评测报告.md)。
