## 优先验证的原因

RoutedChatService已完成名称去重与规范化，但生成器只接收question和context。模型还需自行解释原问题两个名称的关系，可能保守判定需要两份不同产品资料，或认为缺少差异信息。

没有模型内部推理日志，不能断言其每次具体推理；“确定性任务事实未传入生成”是从接口与代码观察到的缺口，应通过受控对照验证。

## 最小修复候选

把服务端的规范型号与重复提及事实作为任务上下文传给新版routed生成路径，原问题保留：

1. 只有一个已知规范型号、无未知提及、重复名称均归到同一型号时启用此提示。
2. 告知模型这是单型号演示规则问答，不因重复名称就要求另一型号的资料。
3. 可说明当前资料中的同一套规则及边界，不能断言所有订单、渠道或批次完全相同。
4. 条款、价格、参数等关键事实缺失时仍返回证据不足；不得强制answerable=true。
5. 原无过滤chat保留基线，不读取caseId、金标准或expectedAnswerPoints，不硬编码A2期限。

当前topK已召回需要的规则，提高K不是首要修复。改标签或全局减少拒答也不符合证据约束。
