# 型号识别与澄清接口设计

日期：2026-10-08。状态：用户授权助手写入实现，构建与接口已验证。完整代码保留在[型号识别与澄清完整代码教程](型号识别与澄清完整代码教程.md)，实际范围与限制见[验证报告](../datasets/evaluation/model-recognition-v1/验证报告.md)。

## 1. 本阶段目标

已完成的型号过滤依赖调用方传入正确productModel。本阶段把用户问句中的型号转换为可信的规范型号，同时明确缺失、未知和多型号情况。先提供独立识别预览接口，之后另一步接入聊天，避免把识别与回答质量变动混在一起。

本阶段不实现复杂度分类、会话记忆、订单查询、多型号比较回答或多Agent。识别状态不等于问题是否可回答，也不等于证据充分性。

## 2. 路线选择

| 路线 | 优点 | 限制 |
|---|---|---|
| 规范型号目录与规则匹配 | 无模型调用，规则可解释，可重复测试 | 对缩写、错别字、代词与隐含指代能力有限 |
| LLM结构化提取 | 可处理自然表达、纠正和部分上下文 | 增加延迟成本；模型给出的型号仍需目录校验 |
| 规则优先、LLM按需补充 | 保留快路径，同时扩展表达覆盖 | 需要先有两路评测与明确触发条件，暂不一次实现 |

推荐本阶段规则版；收集其实际失败后再决定LLM补充是否值得。

## 3. 型号目录与职责

- 建立应用自己的规范型号目录：SoundBee-A1加扩展语料的10个型号，共11个。
- 目录只保存规范名称与显式别名，不读取评测问题、金标准来源或policy-catalog的答案参数作为运行时判断依据。
- 首版接受完整规范名及其大小写变化，统一映射为入库使用的规范大小写。
- 暂不自动支持裸A2、A2Plus、中文品牌别名、空格拼写或模糊纠错。这些是后续可独立评测的扩展，不能靠删除任意字符后猜型号。
- 新型号须登记目录并有适用资料；本阶段目录不是数据库自动发现型号，也不保证资料已经入库。

目录解决“允许识别哪些名字”；识别服务解决“问句实际提及什么”；决策服务输出状态与追问建议。初版可用一个识别服务承载后两项，避免只有几条规则就拆成大量Agent。

## 4. 明确的匹配与状态规则

1. 对完整名称做大小写不敏感匹配，但型号边界不允许继续接英文、数字、下划线或连字符。A2不能成为A2-Plus、A2Plus或A2-Unknown的部分命中。
2. 以完整SoundBee-型号形态捕获提及，逐项查目录；未知后缀不能通过已知前缀混进结果。
3. 同一规范型号重复出现只计一次，保留首次出现顺序；原文提及保留用于解释。
4. 没有品牌完整型号时返回MISSING，不能从相似检索结果或默认A1推断。
5. 一种已知型号、没有未知提及，返回RESOLVED。
6. 任一完整型号提及不在目录时返回UNKNOWN；同时返回已知与未知提及，不能只丢弃未知部分继续检索。
7. 只有已知提及但有多个不同型号时返回MULTIPLE，保留全部型号，productModel为空。此状态表示不能走单型号路径，不代表用户问题错误；比较问题随后可走多型号流程。
8. 否定或纠正句首版不做语义选择，例如“不是SoundBee-A2，是SoundBee-A3”保守返回MULTIPLE，明确本版不判断哪个提及是最终目标。

目前只接受这一品牌的演示完整名称。其他品牌或仅有订单号属于识别范围外，不查询订单、不调用模型补猜。

## 5. 接口草案

接口：POST /api/v1/routing/model。放在routing/controller、routing/dto、routing/service，保持项目按业务模块组织的约定。

请求只包含question，沿用非空与最大1000字符的校验。

响应字段：

| 字段 | 含义 |
|---|---|
| status | RESOLVED、MISSING、UNKNOWN、MULTIPLE |
| productModel | 仅RESOLVED时填规范型号，否则为null |
| detectedModels | 已知规范型号，去重并保留顺序 |
| unknownMentions | 原始未知型号提及 |
| mentions | 全部原文提及，保留重复与顺序，便于核对提取过程 |
| message | 中文说明或澄清建议，不生成政策答案 |

HTTP200用于上述四种有效识别结果；空问题或超过长度的请求返回400。不能把UNKNOWN当作HTTP500，不能把识别失败伪装成检索无证据。

RESOLVED可以进入已验证的型号过滤检索。MISSING在型号专属政策场景需要询问型号；通用配送问题可能不需要型号，未来业务路由决定，不能把所有MISSING一律转人工。UNKNOWN提示核对型号。MULTIPLE提示当前包含多个型号；比较请求应交给未来多型号路径，不擅自只选一个。

该接口没有权限管理职责，不以型号过滤替代订单授权。

## 6. 验收示例

| 问句 | 预期状态与结果 |
|---|---|
| SoundBee-A2怎么配对？ | RESOLVED，规范A2 |
| soundbee-a2怎么配对？ | RESOLVED，映射规范A2 |
| SoundBee-A2-Plus怎么配对？ | RESOLVED，仅Plus，不能同时出现A2 |
| SoundBee-A2能退吗，SoundBee-A2坏了 | RESOLVED，重复提及去重 |
| 耳机坏了能退吗？ | MISSING |
| A2怎么配对？ | MISSING，首版不接受裸缩写 |
| SoundBee-Z9能换货吗？ | UNKNOWN，保留Z9原文 |
| SoundBee-A2Plus能换货吗？ | UNKNOWN，不截断为A2 |
| SoundBee-A2-Unknown能换货吗？ | UNKNOWN，不截断为A2 |
| SoundBee-A2和SoundBee-A2-Plus保修有什么区别？ | MULTIPLE，保留两型号 |
| 不是SoundBee-A2，是SoundBee-A3 | MULTIPLE，首版不处理语义纠正 |
| SoundBee-A2与SoundBee-Z9有什么区别？ | UNKNOWN，同时保留已知A2与未知Z9 |
| 我的订单12345什么时候到？ | MISSING，不假装已查订单 |

测试还需覆盖空白与超长请求、中文紧邻型号、重复提及顺序、完整后缀与大小写边界。识别测试集合单独建立，不修改现有检索金标准，不使用保留验证问题调规则。

## 7. 实施与评测顺序

1. 用户确认本设计后，先提供规范目录、请求/响应、识别服务、控制器及测试的完整文件代码和中文注释。
2. 用户写入并编译，助手执行识别接口测试；记录各状态混淆、精确型号匹配、子型号误识别、假RESOLVED和规则覆盖范围。
3. 接入聊天另做设计：仅RESOLVED进入单型号检索，其余由适用业务流程澄清或分流；聊天新状态不能与旧两种状态悄悄混用。
4. 型号识别加检索的端到端评测与“人工正确型号过滤”分开报告，计入识别失败，不能只测RESOLVED的问题。
5. 根据规则失败样本再评估别名与LLM兜底，不预设效果数字。
